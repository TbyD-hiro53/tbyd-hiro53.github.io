# Earth v7 室内ベイクの再制作

必要環境: Blender 4.3.2 / Cycles、Python 3 + numpy + Pillow + Playwright、Chromium、oidn 0.2.1（OIDN 1.4.3）。公開サイトの起動にこれらの制作ツールは不要。OIDNの共有ライブラリはパッケージの `lib.linux.x64` を用いる。別の場所なら `OIDN_LIBRARY` に実パスを設定し、共有ライブラリ検索パスにも追加する。

1. HTTPでリポジトリを起動し、Earthのプレビューが起動できる状態にする。
2. `export.py` で静的な室内・器具・家具・接合部を取得。分類にはサイト本体の `earth-origin-material-v7-20261017-partition.js` を使う。既にv7の合成が有効なら、エクスポート時は元の立体表示へ戻す。動く画面・光点・円盤・透明カバーは対象外。
3. `blender -b -t 4 -P build.py` で室内のシーンを構築。元の法線、UV、頂点色、粗さ・法線テクスチャ、配置を継承する。閉じた壁・床・天井と追加部材を同じ光で計算する。単独の物体へ一律のAOを塗る処理ではない。
4. `blender -b -t 4 -P render.py -- 1 0 2 3` で四つの固定眼点の4096×2048色画像と、Cycles Zの全球深度を保存する。全球の深度は放射距離。透視画像のZとは形式が異なる。
5. `denoise.py` に `interior-0.png` から `interior-3.png` までの実パスを渡す。linear RGBでOIDN RTの色のみをデノイズし、表示用sRGBに戻す。実制作のBlenderビルドには内蔵OIDNが無いため外部処理。
6. `package.py 0 1 2 3` でデスクトップ・小画面用の色をサイトへ、検証用の深度を制作ディレクトリへ出力する。画像の空白側へ縁の色を延長してからJPEG化。実際のブラウザの室内深度は統合した元形状が担う。検証用の深度は64mまでの16bit R/G、65535は開口・空など形状なし。小画面用深度は距離そのものを近傍縮小してから符号化する。
7. ブラウザで4か所、見回し、表示応答、収束、タップ説明、深度の重なりを確認。正常な初期読み込みだけでなく、画像が失敗した場合の立体への復帰も検証する。

`EO_BAKE_DIR` は制作ディレクトリ（既定 `/tmp/earth-v7`）、`EO_REPO_DIR` はサイトルート、`EO_SOURCE_URL` はエクスポート元。画像を内包した `.blend` は独立プレビューZIPの `blender-source/interior.blend` に同梱する。このファイルを `EO_BAKE_DIR/interior.blend` へコピーすれば、手順4から再レンダリングできる。

森はv6のベイクを継承する。対応する元シーンと手順は同梱のforestシーンと `audit/2026-10-17/earth-v6-bake/README.md`。室内を透明な背景で別に焼き、外景と深度で合成するため、背景の森を動く円盤ごと一枚へ固定しない。
