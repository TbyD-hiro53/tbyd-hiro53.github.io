# 環境音・効果音の導入検討 — 2026-10-17

## 結論と範囲

導入可能。今回は検討のみで、音声コードや音源は追加しない。最初の試作は The Carriage Window と Coastal Glass を推奨する。走行・波など画面内の運動と音の関係が明確で、視覚だけでは伝えにくい距離や移動を補える。全作品へ同じ環境音、音楽、タップ音を付ける運用はしない。

現行リポジトリには一般的な音声ファイル形式の資産を確認できなかった。以下は新規制作の提案であり、原典の音響描写を確定するものではない。各作品の実装前に原典・CANONの該当箇所と照合する。

## 作品ごとの方向

| 作品 | 提案 | 守ること |
| --- | --- | --- |
| The Carriage Window | 控えめな走行音、窓外の空気、駅通過時の変化。既存の走行距離・駅の位相と同期 | 駅以外でも移動を感じられる連続性。ナレーション表示を音声読み上げと混同しない |
| Coastal Glass | 遠近のある波音と風。夜は音量と帯域を穏やかに変化 | 灯台の回転自体に機械音を付ける必要はない |
| Earth Origin Material | 外の風・葉擦れ、開口から内部へ入る弱い音 | 森の音が室内でも同じ大きさにならない。鳥・虫などは原典確認後 |
| The Confluence | 水路の静かな水音と間。視点によって距離感を変える | 採用済み設定の「無音の円盤」を維持。円盤の唸り・回転効果音は追加しない |
| Core No.37 / Sanctum / Armillary | 作品固有の動きと関係する音は個別に検討 | 光や回転に必ず音があるとは限らない。音の意味を先に設計する |
| Lacto Caloris | 静けさを基本にする。必要なら操作の補助音を別途検討 | 真空中に空気伝播の機械音が鳴る設定にはしない。非物理的な状態の可聴化は別の創作判断 |

Confluenceの根拠: `next-production-decisions.md`、`confluence-v6-design.md`。水音のみという方向は `audit/2026-10-16/confluence-direction.md` の提案とも整合する。

## 再生とUI

- 初回は消音。明示的な「音を有効にする」操作で AudioContext を開始する。自動再生に依存しない。
- 音の有効・無効と音量を共通の Liquid Glass UI に収める。常時表示の作品説明や視点ボタンを増やして圧迫しない。押しやすさ、フォーカス、消音状態の読み上げも確認する。
- タブが非表示になったらフェードして停止または suspend。復帰時の再開はブラウザ制約を考慮し、失敗した場合に無理に鳴らさない。ページ破棄時に資源を解放する。
- 複数作品を別タブで開く利用があるため、可視タブのみを再生対象とする。複数ウインドウが同時可視の場合の排他は試作時に検討する。
- 説明や操作の意味を音だけに依存させない。現行の文章ナレーションを自動で音声化することは今回の提案に含めない。

## 負荷と構成

事前制作した短いループと少数の単発音を同一オリジンから必要時だけ読み込む。初期試作は同時2〜3層程度。音量と軽いフィルタで距離感を作り、多数の音源を使うリアルタイム音響計算は導入しない。自然なループの継ぎ目、フェード、クリックノイズ対策を素材制作で済ませる。

Web Audio の時刻と作品内の時間・走行距離を対応させる。描画が落ちた際に効果音が連打されない設計にする。停止・視点移動・ページ復帰時は位相の再同期を行う。

負荷の主な増加は音源の通信量・デコード・メモリ。例えば30秒のステレオ48kHz・float32音声は展開後約11.5MB（10.99MiB）。圧縮96〜192kbpsなら素材本体は概算0.36〜0.72MBだが、実際の品質・ループ長・ブラウザ対応形式で変わる。これは予算の目安で、実測結果ではない。長い環境音ではストリーミングも比較し、短い効果音だけをメモリ保持する選択肢がある。

通常の数層の再生なら3D描画への影響を抑えやすいが、無負荷ではない。iPhone/Safariで発熱・電池消費・バックグラウンド移行・再開・メモリを確認する。現在のソフトウェア描画環境のみで実機の音質や負荷を合格にしない。

## 試作の受け入れ条件

1. 消音のままでも現行作品が完全に操作・鑑賞できる。
2. 走行距離、駅通過、波などの見た目と音が矛盾しない。ループの継ぎ目が目立たない。
3. タブ切替・作品移動・停止からの復帰で音の重複や突然の大音量がない。
4. イヤホンと本体スピーカーの両方で、静かな音量でも意図が伝わる。長時間の耳障りな高音・低音を避ける。
5. デスクトップとiPhone/Safariで操作開始・消音・音量・画面ロック後の復帰を実機確認する。
6. 音源は自作・収録・使用条件を確認した素材を使い、出典と編集内容を記録する。

まず二作品で密度と音量の基準を決め、その評価後に他作品へ展開する。
